01

Where to run Claude

It's the same Claude Code agent in every surface. Pick the surface by where the code lives and where you are.

Claude Code: local Main tool

CLI claude
Full agent in your terminal, working on your real repo, tools and credentials.Daily coding. Most power and control.
VS Code / JetBrains
Claude inside the IDE, with inline diffs and your current selection as context. --ide connects the CLI.You want to review diffs visually as you go.
Desktop app
GUI for local and cloud sessions side by side.Running several sessions and switching between them.
Tip: If you use WSL, run the CLI inside WSL where the code lives, not from Windows against \\wsl$ paths.

Claude Code: cloud & remote

Web claude.ai/code
Sessions run on Anthropic-hosted machines against your GitHub repo.Long jobs that shouldn't depend on your laptop staying awake.
claude --cloud "…"
Start a cloud session from the terminal, or attach to one.Fire off several independent tasks at once.
/teleport
Send this session to the cloud, or pull a cloud session down to your terminal.You started locally and need to leave, or the reverse.
/remote-control
Drive your local session from claude.ai or the mobile app.You need your local tools, VPN or kube context, while away from your desk.
Mobile app
Check on, answer and steer cloud and remote sessions. Get push notifications.Approving or unblocking a running task on the go.
Tip: Cloud sessions can't reach your private network. Use Remote Control when the task needs internal hosts.

Claude Code: integrations

GitHub Actions
Mention @claude in a PR or issue to review, fix or implement. Set up with /install-github-app.Team-wide review help, or small fixes from issues.
Claude in Slack
Mention @Claude in a channel to start a coding task from the thread. /install-slack-app.A bug report arrives in Slack and you want a first fix. Needs workspace approval.
Claude in Chrome --chrome
Claude drives your browser: clicks, reads the console, takes screenshots.Checking an admin UI or API docs page end to end.

claude.ai: rest of your plan

Chat + Projects
Chat with project knowledge that persists (specs, ADRs, runbooks).Thinking through designs away from the repo, or writing docs.
Research
Searches many sources and writes a report with citations.Comparing technologies: "Kafka vs NATS for our case".
Connectors
Lets Claude read Jira/Confluence, Slack, Drive, Gmail, Calendar, Linear, Notion, Figma and more.Answers that need company context. Authorize each one once.
Artifacts
Private, shareable pages: reports, dashboards, diagrams, decks, docs. Also available from Claude Code (/artifacts).Sharing an incident write-up or a design comparison.
Cowork (Desktop)
An agent for knowledge work on the files on your computer.Non-code tasks: organizing notes, making spreadsheets, drafting documents.

Models, effort & speed

Switch with /model <alias> or claude --model <alias>. Bigger models and higher effort use more of your plan's limit, so match them to the task.

Most capable

Fable 5.1

fable · claude-fable-5-1
Reasoning
Usage cost
  • Hard design and architecture
  • Subtle concurrency or distributed bugs
  • Large, tricky refactors
Frontier default

Opus 5.5

opus · claude-opus-5-5
Reasoning
Usage cost
  • Everyday feature work
  • Long agentic sessions
  • Code review, debugging
Balanced

Sonnet 5

sonnet · claude-sonnet-5
Reasoning
Usage cost
  • Routine, well-defined tasks
  • Tests, boilerplate, docs
  • Stretching usage limits
Fast & light

Haiku 4.5

haiku · claude-haiku-4-5
Reasoning
Usage cost
  • Quick lookups and small edits
  • Cheap subagents for searching
  • Hooks and scripts using -p

Effort: how hard the model thinks

Set with /effort <level> or --effort. Higher effort means more reasoning, slower answers and more usage. Toggle /fast for faster output from the same model. It uses the same model at the same quality, but it can cost more, so check /usage.

lowRenames, formatting, quick answers
mediumRoutine features and fixes
highMulti-file changes, debugging
xhighArchitecture, gnarly bugs
maxWhen lower levels failed
03

Permission modes

Press Shift+Tab to cycle modes during a session, or start with --permission-mode <mode>. Pick the mode by how much you trust the task and the environment.

From most control to least

plan
Reads and explores only. Proposes a plan and makes no changes. Ctrl+G opens the plan in your editor.Unfamiliar code, risky changes, anything that touches several files.
manual (default)
Asks before every edit and every command that isn't allowlisted.Sensitive repos, or when you're learning what Claude does.
acceptEdits
File edits and safe filesystem commands run without asking. Other commands still ask.After you've approved the plan. Review with git diff.
auto
A classifier approves safe actions and stops risky ones. Inspect it with claude auto-mode.Long tasks where approval prompts would slow you down.
dontAsk
Runs only allowlisted tools and denies everything else without asking.CI and scripts with an exact allowlist.
bypassPermissions
No checks at all.Only in a throwaway container with no secrets or network. Never on your laptop.

Fewer prompts, still safe

/permissions
Manage allow and deny rules, e.g. Bash(go test *).You approve the same safe command again and again.
/fewer-permission-prompts
Reads your history and suggests an allowlist of read-only commands you use often.Once, early on, then every few weeks.
/sandbox
The OS limits which files and network hosts Bash can reach, so more commands can run without prompts.You want autonomy with a hard boundary in place.
--allowedTools / --disallowedTools
Set allow and deny lists for one run.Headless runs and one-off scripts.
--add-dir · /add-dir
Give access to another directory, such as a shared protos repo.A change spans two repos.
Rule: Deny rules win over allow rules. Deny reads of .env, ~/.aws, and *.pem in user settings once, and they apply to every project.
04

Session & context control

Context is Claude's working memory, and the most important thing to manage. When it gets cluttered, answers get worse.

Context Manage every day

/context
Shows what's filling the context window: files, tools, MCP servers, memory.Answers get vague, or you suspect MCP tools are bloating it.
/clear
Starts fresh. CLAUDE.md loads again.Every time you switch to an unrelated task. Do this often.
/compact [focus]
Summarizes history to free space. Add a focus, e.g. /compact keep the API contract and failing tests.Same task, but a long session.
/btw <q>
Ask a side question without disrupting the main thread."What does this flag do again?" in the middle of a task.
--autocompact
Set the size at which auto-compaction starts.Tuning very long sessions.

History, undo & resume

Esc
Stop Claude mid-action. Context is kept.It's going the wrong way. Stop early.
Esc Esc · /rewind
Restore the code, the conversation, or both to an earlier checkpoint.Undo an approach and try another.
claude -c
Continue the most recent session in this directory.Picking up where you stopped yesterday.
claude -r · /resume
Choose any past session to resume. Add --fork-session to branch off a copy.Going back to an older thread, or trying an alternative.
--from-pr 123
Resume the session linked to a PR.Addressing review comments on that PR.
-n <name>
Give the session a name, shown in the picker and the terminal title.Several sessions open at once.
/export
Save the conversation to a file or the clipboard.Attaching the reasoning to a ticket or PR.
Note: Checkpoints track Claude's file edits, not changes made by shell commands, databases or deploys. Commit before risky steps.

Input shortcuts

@path/file.go
Add a file or folder to the context.You know exactly which code matters.
! <cmd>
Run a shell command yourself. Claude sees the output.Interactive logins, or showing Claude real output.
Paste an image
Screenshots of dashboards, diagrams or errors.A Grafana panel shows the problem better than words.
cat log | claude -p
Pipe data straight in.Quick log or JSON analysis.
Shift+Tab
Cycle permission modes.Switching into or out of plan mode.
Ctrl+G
Edit the plan or prompt in your $EDITOR.Refining a plan before you approve it.
/keybindings
Customize shortcuts.A default key clashes with your terminal.

Session settings & health

/usage
Session cost, plan usage, and what's using up your limits.Before starting a heavy job, and weekly.
/config
Theme, notifications, output style, defaults.First-time setup.
/output-style
Change how Claude responds: explanatory, learning, and so on.Learning a new area and you want it to teach as it works.
/statusline
Custom status bar showing model, branch, context use.You want context use always visible.
/doctor · --safe-mode
Diagnose your install, or start with all customizations turned off.A plugin, hook or MCP server is misbehaving.

Extend & customize

Write down what you'd otherwise repeat. Choose the right mechanism: memory is advice Claude reads, skills are procedures it runs on demand, hooks are rules that always run, and MCP gives it access to other systems.

Memory: CLAUDE.md

/init
Generates a starter CLAUDE.md from the repo.The first session in any repo.
./CLAUDE.md
Project memory, committed and shared with the team. Loaded every session.Build and test commands, conventions, gotchas.
~/.claude/CLAUDE.md
Your personal memory, used in every project.Your own preferences: style, commit habits.
Subdir CLAUDE.md · .claude/rules/
Loaded only when Claude works in that path, or on files that match the rule.Monorepos, or rules for specific areas (migrations, protos).
/memory
Edit memory files and auto-memory settings.Claude keeps making the same mistake.
Best practice: Keep it short (under ~200 lines). Record only what Claude can't work out for itself. Every line is loaded every session.

Skills & slash commands

.claude/skills/x/SKILL.md
A packaged procedure or reference. Claude loads it automatically when relevant, or you run it as /x.Repeatable workflows: release steps, a review checklist, an incident runbook.
~/.claude/skills/
Personal skills, available in every repo.Your own habits, e.g. a devlog or status-update format.
/skill-name args
Run a skill explicitly.You want exactly that workflow and no guessing.
Best practice: The skill's description decides when it triggers, so write it carefully. Keep the SKILL.md body short and put long reference material in files next to it.

Subagents

"use a subagent to…"
Runs in its own fresh context and returns only a summary to your session.Searching a big codebase, research, or an independent check.
/agents
Create and manage custom agents in .claude/agents/*.md, each with its own prompt, tools and model.A specialist you use often, such as a race-condition reviewer.
--agent <name>
Run the whole session as that agent.A dedicated reviewer or triage session.
Built-ins
Explore (read-only search), Plan (designs an approach), general-purpose.Claude picks these itself. You can also ask for one by name.
Best practice: Use subagents to keep your main context clean, and to verify work with fresh eyes. A reviewer that didn't write the code catches more.

Hooks: guaranteed automation

/hooks
Commands that run on lifecycle events. Configured in settings.json.Something must happen every time, not just usually.
PreToolUse
Runs before a tool call and can block it.Block edits to vendor/, block kubectl delete, block writing secrets.
PostToolUse
Runs after a tool call.Run gofmt/goimports or a linter after every edit.
Stop · Notification
Runs when Claude finishes or needs you.Desktop or phone alerts, so you can walk away.
SessionStart · UserPromptSubmit
Add context at the start of a session, or check prompts as they're sent.Load the current branch or ticket automatically.
Rule of thumb: If CLAUDE.md says "always do X" and Claude sometimes forgets, turn it into a hook.

MCP servers & connectors

claude mcp add
Connect external tools: Jira, Grafana, databases, internal APIs.Claude needs live data from a system it can't reach otherwise.
/mcp
See status, sign in, turn servers on or off.A server needs authentication, or is using too much context.
.mcp.json
MCP servers for the project, committed so the team shares them.Everyone on the repo needs the same tools.
claude.ai connectors
Connectors you authorize on claude.ai also appear in Claude Code.Atlassian, Slack, Drive and others, set up once.
Best practice: Every connected server's tools take up context. Turn off servers you're not using. Prefer a CLI (gh, kubectl, aws) when one exists.

Plugins & settings

/plugin
Install bundles of skills, agents, hooks and MCP servers from marketplaces.Getting a team's whole toolkit in one step.
claude plugin
Manage plugins from the shell: install, update, add a marketplace.Scripted setup, or bootstrapping a new machine.
--plugin-dir
Load a plugin from a local folder for this session only.Developing or testing your own plugin.
Settings scopes
~/.claude/settings.json (you) → .claude/settings.json (team) → .claude/settings.local.json (you, this repo). Managed policy overrides all of them.Put team rules in project settings and personal preferences in user settings.
claude import
Import config from another AI coding agent.Moving from a different tool.

Parallel, background & automation

Run several sessions at once. You direct the work and check the results.

Parallel work

claude -w <name>
New git worktree, so the session gets its own isolated checkout. Add --tmux for a pane.Two or more tasks in the same repo that must not step on each other.
claude --bg "…"
Start a session in the background. It prints an id.A long task while you keep working in the foreground.
claude agents
List background sessions. Then use attach <id>, logs <id>, stop <id>, rm <id>.Checking on and managing the sessions you started.
/tasks
See and manage everything running in the background of this session.A background build, test or subagent is still going.
Best practice: Give each parallel task its own worktree and a narrow goal. Review them one at a time. Three sessions you've checked are worth more than ten you haven't.

Keep working without you

/goal <condition>
Claude keeps working until the condition holds, and checks it before stopping."all tests pass and go vet is clean", or "the benchmark beats main".
/loop 10m <prompt>
Repeat a prompt on an interval. Leave out the interval to let Claude set the pace.Watching CI, a rollout, or a queue draining.
/schedule
Cloud routines that run on a cron schedule, even when your machine is off.Daily dependency check, weekly stale-PR summary, a morning error-log digest.
Best practice: Use a /goal you can check with a command. "Make it better" isn't a goal. "The TestLogin* tests pass" is.

Headless & programmatic

claude -p "…"
One-shot, non-interactive run that prints the result.Scripts, git hooks, Makefile targets.
--output-format json
Machine-readable output. stream-json streams it as it runs.Passing the result to jq or another tool.
--json-schema '{…}'
Makes the output match a schema you give it.You need structured data you can rely on, e.g. a triage verdict.
--fallback-model
Automatically switch to another model if the main one is overloaded.Unattended jobs that must finish.
Agent SDK
Build your own agents in Python or TypeScript on the same engine.Internal bots and custom pipelines.
07

Quality gates

These are built in. Run them on every change before a person reviews it.

Review commands

/code-review [level]
Looks for correctness bugs in the current diff, a PR or a path. Levels: low to max. --fix applies the fixes and --comment posts them on the PR.Before every commit or PR.
/security-review
Security review of the changes on your branch.Anything touching auth, input parsing, SQL, secrets or permissions.
/ultrareview · claude ultrareview
Several agents in the cloud find bugs and check each other's findings.Large or risky branches: migrations, concurrency, payment paths.
/simplify
Finds code to reuse, simplify or speed up, then applies the changes. It doesn't look for bugs.After the feature works, before review.

How to verify

Tests first
Ask for failing tests before the fix. The test becomes the contract.Bug fixes and new behavior.
Give a check command
"Run go test -race ./... and golangci-lint run and fix everything."Always. Claude improves a lot when it can check its own work.
Fresh reviewer
A second session or subagent reviews the diff without the author's context.Important changes. Removes the author's bias.
You read the diff
Every line that ships is yours.Always. Never merge something you can't explain.
08

Principles for any AI tool

These apply to Claude Code, chat, and every other AI tool you'll use.

You own the outputAI writes the draft. You are accountable for what ships, in review, in production and on call.
Context beats clevernessGive it the goal, constraints, relevant files and what "done" means. Vague input gets generic output.
Explore → Plan → Code → CommitFor anything non-trivial, have it read and plan before writing code. Fixing a plan costs far less than fixing code.
Give it a way to check itselfTests, linters, a benchmark or an expected output. If it can check, it can fix its own mistakes.
Small steps, fast feedbackSmall diffs you can fully review. Commit often, so you can roll back.
Stop earlyStop it the moment it drifts. Two failed corrections means /clear and a better prompt.
Fresh context beats long contextOne task per session. Long, cluttered sessions give worse answers.
Write it down onceIf you've said it twice, put it in CLAUDE.md, a skill or a hook.
Trust, but verifyAI can be confidently wrong about APIs, versions and concurrency. Compile, test and read the code.
Protect secrets and dataNever paste credentials or customer data into prompts. Use deny rules and redact logs.
Right-size the modelUse a small model for routine work and the big one for hard problems. Your usage limit is a budget.
Use it to learn, not to skip learningAsk "why", and ask for trade-offs. Keep the hard thinking for yourself.

✓ Prompts that work

  • "Read internal/auth and explain the token refresh flow before changing anything."
  • "Follow the pattern in orders/handler.go. Don't add new dependencies."
  • "List 3 approaches with trade-offs. Don't write code yet."
  • "Write a failing test that reproduces this, then fix it."
  • "What could break under concurrent requests? Check for races."
  • "Interview me about the requirements before you plan."

✗ Habits to avoid

  • "Fix the bug", with no error, file or expected behavior.
  • One session for five unrelated tasks.
  • Approving a 2,000-line diff because the tests pass.
  • Pasting .env, tokens or production customer data.
  • Correcting the same mistake over and over instead of /clear and a better prompt.
  • Running bypassPermissions on your real machine.
09

Workflow recipes

Combine the tools above into repeatable workflows. Once a recipe works for you, save it as a skill so you can run it with one command.

Feature from a ticket

Paste ticket + acceptance criteria→ Plan mode · approve→ /goal tests pass→ /code-review→ Commit + PR description

With a Jira or Linear connector, Claude can read the ticket itself.

Hard bug

Paste trace + logs→ "Rank 3 hypotheses"→ Failing test→ Fix→ go test -race

Use /model fable with high effort if the first attempt goes in circles.

Large migration

Plan mode: inventory→ Split into chunks→ claude -w per chunk→ /ultrareview

Examples: a linter major-version upgrade, an SDK bump or an API rename across services.

Production incident

Metrics + logs via MCP or paste→ "Build a timeline"→ Verdict: infra or code→ Artifact write-up

AI builds the timeline. You make the call on rollback or fix.

Learning a legacy service

Plan mode→ "Walk me through a request"→ "Draw the flow as a diagram"→ /init CLAUDE.md

Ask a subagent to document each module so your main context stays clean.

PR back from review

claude --from-pr 42→ "Address each review comment"→ Run tests→ Rebase + push

Resuming from the PR brings back the reasoning from when you wrote it.

Performance work

Paste pprof / flame graph→ Benchmark baseline→ Optimize→ /goal benchmark beats baseline

Also ask it to check for goroutine and memory leaks, and whether K8s requests and limits fit real usage.

Daily automation

/schedule a routine→ Check deps, stale PRs, error logs→ Summary to Slack or an artifact

Start with one routine and read its output for a week before you rely on it.

Make your usage limits last

Plan limits cover everything you do: Claude Code, chat, and cloud sessions. Check where yours is going with /usage.

Spend less

Right model
Use Sonnet or Haiku for routine work. Save Fable and max effort for problems that need them.
/clear often
Every message re-sends the whole context. A smaller context costs less and gives better answers.
Subagents for reading
Big searches run in their own context and send back only a summary.
Point, don't paste
Use @file or a path instead of pasting huge logs. Use grep/tail to send only what matters.

Avoid silent drains

Idle MCP servers
Their tool definitions use context in every session. Turn off the ones you don't use in /mcp.
Tight loops
A /loop 1m left running all day adds up. Use sensible intervals and stop loops when done.
Forgotten background agents
Check claude agents, and stop or rm anything you're not using.
Correction spirals
Five rounds of "no, not like that" costs more than /clear and one good prompt.
