The two payoffs

Productivity and quality

Most people think of AI as a speed tool. For a senior engineer, the quality gains can matter more: a reviewer that doesn't get tired, a test writer that looks for edge cases, and a second opinion on every design.

Productivity

Ship more in the same hours

  • Scaffolding and boilerplateHandlers, DTOs, gRPC or REST stubs, config wiring and Dockerfiles, written in minutes.
  • Codebase navigation"Where is the token refresh handled?" gets answered across services without you grepping for 30 minutes.
  • Large refactors and migrationsLibrary upgrades, API version bumps and lint migrations applied across hundreds of files.
  • Debugging helpPaste the stack trace, logs or pprof output and get ranked hypotheses to test.
  • Writing you'd rather skipPR descriptions, commit messages, runbooks, ADR drafts and status updates.
  • Learning unfamiliar techGet productive in a new queue, database or framework in hours, not days.

Quality

Catch more before production does

  • Edge-case test generationTable-driven tests for nil inputs, boundaries, timeouts, retries and partial failures.
  • Concurrency reviewFlags data races, goroutine leaks, unclosed channels and missing context cancellation.
  • Security reviewInjection, authz gaps, secrets in logs, unsafe deserialization and missing input checks.
  • Observability gapsMissing spans, unstructured logs, wrong log levels and metrics with high cardinality.
  • Design critiqueStress-tests your design: failure modes, idempotency, back-pressure and data consistency.
  • Docs that match the codeOpenAPI specs, READMEs and comments kept in line with what the code actually does.

How to work with it

The senior engineer's AI loop

Treat AI like a very fast mid-level engineer who knows almost nothing about your system. The quality of what you get back depends on the context you give it and how carefully you check it.

1
You

Specify

Give it the goal, constraints, SLOs, schema, and the files or patterns to follow. Say what "done" means.

2
AI

Delegate

Let it draft, search, refactor or test. Keep each task small enough that you can review the whole diff.

3
You

Verify

Run the tests, read the diff, and check it against how the real system behaves. Never merge code you don't understand.

4
Together

Refine

Correct it, add the context it lacked, and repeat. Save what you learn in project docs such as CLAUDE.md so the next run starts smarter.

Better input, better output

How to write a good backend prompt

Vague prompts get you generic code. Specific prompts get you code that fits your system.

Goal
Add idempotency to POST /v1/payments so client retries never double-charge.
Context
Go 1.23, Postgres, Redis available. Follow the pattern in internal/orders/handler.go.
Constraints
p99 < 50ms added latency. No new infrastructure. Keys expire after 24h.
Failure modes
Handle two requests with the same key at once, Redis being down, and a crash between the write and the response.
Done means
Table-driven tests for every failure mode above, go test -race passes, and the PR description explains the trade-offs.
Use it safely

Risks and how to guard against them

AI can be confidently wrong. These guardrails keep the speed gains from turning into production incidents.

Invented APIs

It calls library functions or config flags that don't exist, or that changed versions ago.

Guard: compile and test every change. Point it at your real dependency versions.
Subtle concurrency bugs

Code that looks right can still race, deadlock or leak under load.

Guard: run -race, load tests, and your own review of every shared state change.
Leaking secrets

Credentials, customer data or tokens pasted into prompts or committed into generated code.

Guard: use approved tools only, redact logs before pasting, and run secret scanning in CI.
Trusting it too much

Approving large diffs because they "look fine" and the tests pass.

Guard: keep diffs small. If you can't explain the code, don't merge it.
Inconsistent code

Each generated piece uses a different style, error pattern or logging convention.

Guard: write your conventions down in project docs and linters, and point AI at them.
Skills getting rusty

Handing off the hard thinking, not only the typing.

Guard: use AI to go deeper. Ask "why", and still solve the hard parts yourself.
Start this week

Seven things to try first

Choose one. Use it every day for a week, then add another.

  • Ask AI to review every PR before a person does. Focus it on races, error handling and security.
  • Write tests before you trust generated code. Let AI draft the edge cases and you check them.
  • Add a CLAUDE.md or similar file to each repo. Record conventions, build commands and gotchas once.
  • Use AI to learn an unfamiliar codebase. Ask for a walkthrough and a diagram of a request's path.
  • Ask for a critique of your next design doc. Ask what fails at 10x load or during a partial outage.
  • Hand off a tedious migration. A lint upgrade, SDK bump or API rename, done in reviewable chunks.
  • Use AI in your next incident. Give it the metrics and logs, and ask whether it's infra or code.
AI won't replace a senior engineer. It gives you more time for the hard problems.

Specify clearly. Delegate the mechanical work. Verify everything. Keep ownership of what you ship.
